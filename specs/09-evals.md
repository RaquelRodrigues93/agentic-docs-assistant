# 09 — Evals

Status: `accepted` · Phase: 3

## Goals

- A versioned golden dataset and a runner that scores **retrieval** (deterministic, free) and
  **answer quality** (LLM-as-judge with a structured rubric).
- Scores saved as a report and compared against thresholds; CI fails on regressions.
- The README shows the latest scores, generated by the runner (not edited by hand).

## Golden dataset — `evals/datasets/golden.jsonl` (20 cases)

```python
class GoldenCase(BaseModel):
    id: str                                   # "auth-001"
    question: str
    category: Literal["answer", "unanswerable", "out_of_scope", "action", "injection"]
    expected_sources: list[ExpectedSource]    # empty for out_of_scope/injection
    reference_facts: list[str]                # facts a correct answer must contain (for the judge)
    expected_outcome: Literal["completed", "refused", "awaiting_approval"]

class ExpectedSource(BaseModel):
    source: str                               # "docs/authentication.md"
    section: str | None = None                # match on prefix of heading path; None = any section of the file
```

Mix (≈20): 12 `answer` (single- and multi-section), 2 `unanswerable` (the deliberate doc gaps),
2 `out_of_scope`, 2 `action`, 2 `injection`. Cases are written by hand against `docs/` and reviewed as
code. Changing a case bumps `evals/datasets/VERSION`.

## Metrics

**Retrieval** (calls the `Retriever` directly; no LLM):
- `hit@k` (k=6): the share of cases with ≥ 1 expected source in the top-k.
- `MRR`: mean reciprocal rank of the first relevant chunk.
- `recall@k`: the share of expected sources found (matters for multi-section questions).

**End to end** (runs the graph with the configured provider and a dry-run MCP):
- `outcome_accuracy`: the run status equals `expected_outcome` (this covers refusals and HITL pauses).
- `citation_precision`: the share of returned citations whose source matches an expected source.
- **Judge** (`JudgeVerdict`, judge model = Claude Haiku on Bedrock, or the Ollama judge locally):

```python
class CriterionScore(BaseModel):
    score: Literal[1, 2, 3, 4, 5]
    justification: str = Field(max_length=400)

class JudgeVerdict(BaseModel):
    faithfulness: CriterionScore      # every claim is supported by the cited chunks (no hallucination)
    completeness: CriterionScore      # covers the reference_facts
    relevance: CriterionScore         # answers the question asked
    citation_quality: CriterionScore  # the citations support the claims they're attached to
```

The judge prompt (`prompts/judge/v1.md`) contains the rubric with anchored descriptions for 1, 3 and 5
per criterion. The judge receives the question, the answer, the cited chunk texts and the reference facts,
but **not** the expected sources, to avoid grading on retrieval. Scores are normalized to 0–1.

## Runner

`uv run python -m evals.run --suite retrieval|e2e|all [--judge/--no-judge] [--provider ...]`

- Bounded concurrency (4) with a timeout per case; a failed case counts as a failure and is never skipped.
- Writes `evals/reports/latest.json` (scores, per-case details, dataset version, prompt versions,
  model IDs, git SHA, timestamp) and `evals/reports/latest.md`. `--update-readme` rewrites the block between
  `<!-- EVAL:START -->` and `<!-- EVAL:END -->` in the README.
- Thresholds in `evals/thresholds.yaml`; exits non-zero if any metric is below its threshold. Initial
  thresholds: hit@6 ≥ 0.85, MRR ≥ 0.6, outcome_accuracy ≥ 0.9, faithfulness ≥ 0.8. They are recalibrated
  after the first baseline, and the change is recorded in the PR.

## CI (decision D9)

| Trigger | Suites |
|---|---|
| Every PR | lint, mypy, unit tests, **retrieval evals** (fastembed + Qdrant service container) |
| Push to `main`, PR label `run-llm-evals`, manual dispatch | + **e2e evals with judge** on Bedrock (GitHub OIDC → IAM role limited to `bedrock:InvokeModel*` / `Converse*` on the two model profiles) |

The e2e job uploads the report as an artifact and posts a score summary to the job summary.

## Acceptance criteria

- Dataset validates against `GoldenCase` (a test that loads every line).
- The retrieval suite runs offline in under 2 minutes in CI and gates PRs.
- The e2e suite produces a report with all metrics; the README shows the latest scores.
